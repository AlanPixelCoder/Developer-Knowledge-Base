**Note:**
This module is the Map of Content (MOC) for the HTML notes in this Obsidian vault. Set at the **Tideglass Observatory** on Greyharbor's glass pier, every exercise builds part of a public station site — pier logs, instrument bays, harbor intake forms, and slipway bulletins. HTML provides structure; CSS and JavaScript come later.

**Tip:**
Start at [[01 - Glass Pier Primer]]. Learn to read markup before styling — once structure and presentation are separate in your mind, the rest falls into place.

**Prerequisite:** none. Only a text editor and a modern browser.

> [!NOTE]
> **Tideglass narrative**
> The observatory staff need a public-facing site to publish tide readings, track buoys and instruments, accept harbor intake requests, and post slipway bulletins. Each chapter grows that site one piece at a time, using real HTML elements for a real job at the pier.

## 🎯 Learning Path

1. **Glass Pier Primer** → Publish the morning tide log with text, lists, links and images.
2. **Tideframe Blueprint** → Build a proper skeleton, label cards with classes/IDs, and wire anchors.
3. **Harbor Intake Forms** → Collect structured requests with validation and grouped choices.
4. **Slipway Semantics** → Give the whole site landmarks and accessibility-minded markup.

---

## 🎯 What You'll Be Able To Do

- Write a complete HTML5 page with `<!DOCTYPE html>`, `<head>` and `<body>`.
- Structure pier logs with headings, paragraphs, lists, links and images.
- Label and group elements with attributes, classes, IDs, and style blocks.
- Build forms with validated inputs, radio groups, checkboxes and proper labels.
- Choose semantic elements for regions, articles, navigation and figures.
- Escape special characters so markup is never confused with text.

## 🎮 Practice Philosophy

A station page should be readable as text. If you can read the markup, you can write it. After every small change, open the file in a browser. When something looks wrong, inspect with DevTools and compare what you typed to the actual markup. Keep structure separate from presentation as soon as it's practical.
